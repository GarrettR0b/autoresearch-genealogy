# Быстрый и подробный запуск проекта

Подробная инструкция на русском языке для первого запуска `autoresearch-genealogy`.

## Что это за проект

Это не веб приложение и не сервер. Это набор:

- промптов для AI ассистента,
- шаблона генеалогического хранилища,
- готовых рабочих процессов.

Основная идея, вы копируете шаблон в свою рабочую папку, заполняете исходные данные о семье и запускаете промпты в Codex.

## Что нужно подготовить заранее

1. Git.
2. Редактор markdown, лучше Obsidian.
3. Codex или другой агент, который умеет:
   - читать и редактировать файлы,
   - выполнять веб поиск,
   - проходить по шагам проверки.
4. Любые исходные семейные данные:
   - имена,
   - даты,
   - места,
   - фото и документы.

## Шаг 1, получить проект локально

Откройте терминал и выполните:

```bash
git clone https://github.com/<your-org-or-user>/autoresearch-genealogy.git
cd autoresearch-genealogy
```

Если у вас уже есть папка проекта, достаточно перейти в нее:

```bash
cd /путь/к/autoresearch-genealogy
```

## Шаг 2, создать рабочее хранилище генеалогии

Важно, работать лучше не внутри корня репозитория, а в отдельной папке вашего vault.

1. Откройте ваш vault Obsidian.
2. Скопируйте папку `vault-template/` в нужное место.
3. Переименуйте ее, например в `Genealogy/`.

Пример структуры:

```text
YourVault/
└── Genealogy/
    ├── _Index.md
    ├── Family_Tree.md
    ├── Open_Questions.md
    ├── Research_Log.md
    ├── Data_Inventory.md
    ├── Timeline.md
    └── templates/
```

## Шаг 3, заполнить минимальные данные

Откройте `Family_Tree.md` и внесите то, что уже известно.

Минимум для старта:

- ФИО,
- примерные даты рождения и смерти,
- места,
- связи родитель, супруг, ребенок,
- что это за источник, семейная память, документ, архив, сайт.

Если данных мало, это нормально. Промпты рассчитаны на неполную стартовую информацию.

## Шаг 4, добавить документы

1. Отсканируйте или сфотографируйте документы.
2. Разложите файлы по понятным папкам.
3. Обновите `Data_Inventory.md`, чтобы AI видел, какие материалы доступны.

Рекомендации:

- 300 DPI для текстовых документов,
- 600 DPI для фотографий,
- названия файлов с датой и типом документа.

## Шаг 5, запустить первую сессию в Codex

Откройте Codex в директории вашего генеалогического vault, не в шаблоне, а в вашей рабочей папке.

Дальше:

1. Откройте `prompts/01-tree-expansion.md` из этого репозитория.
2. Скопируйте содержимое в задачу для агента.
3. Замените все плейсхолдеры, особенно `[VAULT_PATH]`.
4. Добавьте явное правило: писать только по источникам, конфликты фиксировать как конфликты.
5. Запустите выполнение.

## Шаг 6, обязательно выполнить проверку

После первого расширения дерева запустите второй промпт:

- `prompts/02-cross-reference-audit.md`

Он нужен, чтобы:

- найти противоречия,
- убрать ошибочные слияния фактов,
- повысить надежность дерева.

## Практическая схема работы, самый надежный вариант

Используйте цикл:

1. Расширение дерева.
2. Аудит расхождений.
3. Разбор открытых вопросов.
4. Повтор.

После каждого цикла проверяйте:

- сколько новых людей добавлено,
- сколько утверждений имеют источники,
- какие конфликты остались нерешенными.

## Частые ошибки и как их избежать

1. Запуск без заполненного `Family_Tree.md`.
   - Исправление, сначала внесите базовую структуру семьи.
2. Отсутствие пути `[VAULT_PATH]`.
   - Исправление, укажите полный абсолютный путь.
3. Смешивание конфликтующих источников в один факт.
   - Исправление, храните версии отдельно и помечайте как конфликт.
4. Отсутствие журнала поиска.
   - Исправление, ведите `Research_Log.md` после каждого запуска.

## Минимальный чеклист первого запуска

- Репозиторий скачан.
- `vault-template/` скопирован в ваш vault.
- `Family_Tree.md` заполнен базовыми данными.
- Документы добавлены и занесены в `Data_Inventory.md`.
- Выполнен `01-tree-expansion`.
- Выполнен `02-cross-reference-audit`.
- Проверены конфликты и открытые вопросы.

## Что запускать после первого успешного цикла

Дальше выбирайте по цели:

- Поиск захоронений, `prompts/03-findagrave-sweep.md`.
- Проверка GEDCOM, `prompts/04-gedcom-completeness.md`.
- OCR поток для сканов, `workflows/ocr-pipeline.md`.

## Коротко, как лучше реализовать процесс

Лучший практический вариант:

1. Один vault на один исследовательский проект.
2. Четкая структура папок и имен файлов.
3. Короткие итерации, но регулярные.
4. Строгая дисциплина источников, без догадок.
5. Отдельный список нерешенных противоречий, до их закрытия.

Так вы получаете воспроизводимый и проверяемый результат, а не просто красивый текст.
